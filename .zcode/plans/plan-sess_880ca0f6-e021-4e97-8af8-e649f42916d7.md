# CredLens — AI Powered MSME Credit Intelligence Platform
## Full-Stack Prototype Implementation Plan

## 1. Goal
Build a runnable full-stack prototype of **CredLens** that matches the 4-layer architecture in your block diagram. Dealers (lenders/banks/NBFCs) can pull an MSME, the system runs the MSME's data through ingestion → AI analytics → decision engine → infrastructure, and returns a credit score, risk grade, recommended limit, and approve/review/reject decision with explainable reason codes — before the dealer transacts with the MSME.

## 2. Tech Stack (confirmed)
- **Backend:** Python 3.13, FastAPI, SQLAlchemy 2.x, SQLite (dev) → easy switch to Postgres for prod
- **ML/Scoring:** scikit-learn (synthetic model) + custom rule layer
- **Frontend:** React 18 + Vite + TypeScript + TailwindCSS, React Router, Recharts, Axios
- **Auth:** JWT (dealer / MSME / admin / govt roles)
- **Data:** Faker-generated synthetic MSME dataset (50–100 sample companies) seeded on first run
- **Tooling:** uvicorn backend, npm for frontend, `run.py` orchestrator to launch both

## 4. Layer-by-Layer Build (mirrors the diagram)

### Layer 1 — Data Ingestion (`services/ingestion_service.py` + `api/ingestion.py`)
- `POST /ingest/financial` — accepts bank statements, GST returns, ITR, balance sheet (JSON or CSV)
- `POST /ingest/business` — invoices, purchase orders, bills
- `POST /ingest/alternative` — utility payments, telecom, digital footprint
- `POST /ingest/government` — simulated MCA / GSTN / Udyam / CIBIL pulls
- `POST /ingest/manual` — file upload
- Each endpoint runs the data through: parse → clean (null handling, currency normalization) → validate (schema check, GSTIN format, PAN format) → dedup → write to `msmes` + `score_run` tables
- All operations logged in `audit_log`

### Layer 2 — AI & Analytics Engine (`services/feature_engine.py` + `risk_scorer.py`)
- `feature_engine.build_features(msme_id)` produces a feature vector: revenue trend, GST compliance ratio, debt-to-income, utility payment consistency, vintage, sector risk, etc.
- `risk_scorer.score(features)` runs the **hybrid** engine:
  1. **Rule layer** (transparent, 0–300 floor): GST compliance < 60% → hard penalty, bounced cheques → hard reject
  2. **ML layer** (300–900 score): GradientBoosting trained on synthetic labeled data, saved to `backend/app/ml/artifacts/model.pkl`
- Output: `credit_score` (300–900), `risk_grade` (A/B/C/D/E/F), `red_flags[]` (e.g. "Revenue declined 3 quarters", "Concentration risk: 78% revenue from 1 buyer")

### Layer 3 — Business Logic & Decision Engine (`services/decision_engine.py` + `api/decision.py`)
- `policy_engine` evaluates dealer-configurable rules from the `policy` table (e.g. min score by sector, max exposure, mandatory GST filing count)
- `limit_engine` recommends credit limit: `limit = avg_monthly_revenue × multiplier(grade) × policy_factor`
- `decision_engine` returns: `APPROVE` | `REVIEW` | `REJECT` + reason codes (e.g. "GRADE_C_THRESHOLD_NOT_MET", "MISSING_GST_FILINGS_2_OF_6")
- All decisions persisted in `decisions` table for audit

### Layer 4 — Platform Infrastructure
- Implemented as cross-cutting concerns in FastAPI middleware:
  - **Security & Privacy:** JWT auth, role-based access control (4 roles), password hashing (bcrypt), request body size limits
  - **Database:** SQLAlchemy ORM, both structured (users, policies) and unstructured (uploaded docs stored as JSON or base64)
  - **Cloud Hosting abstraction:** `config.py` reads `DATABASE_URL` — defaults to SQLite, swap to Postgres for prod
  - **APIs & Integrations:** versioned `/api/v1/*` routes, OpenAPI auto-generated
  - **Monitoring & Logging:** structured JSON logs, every API call logged with user, latency, status — visible in `/admin/model-monitor`
  - **Backup & DR:** `seed.py` + `data/` folder can be tarred; documented restore procedure in README

### Feedback Loop
- Lenders can submit actual outcomes (paid on time / delayed / NPA) via `POST /feedback`
- Outcomes are written to `audit_log` keyed to the originating `score_run`
- `train_synthetic.py` can be re-run with feedback appended to retrain the model
- Model version + accuracy surfaced in `/admin/model-monitor`

## 5. Outputs (4 dashboards, one per user type in the diagram)

| Role | Path | Key screens |
|---|---|---|
| **Lender / Bank / NBFC** | `/lender/*` | Search MSME → see full credit report (score, grade, limits, red flags, reason codes), queue of decisions, portfolio dashboard |
| **MSME** | `/msme/*` | Own credit health score, improvement tips, upload data, score history |
| **Government / Ecosystem** | `/government/*` | Portfolio-level MSME credit insights, sector distribution, grade mix |
| **Platform Admin** | `/admin/*` | User management, model monitoring (drift, accuracy, version), audit log |

## 6. Synthetic Data & Demo Flow
- On first run, `seed.py` populates 50 MSMEs across manufacturing, retail, services, IT — with varied financials, GST compliance, and 6-month history
- Pre-trained ML model shipped in `backend/app/ml/artifacts/`
- Demo flow: log in as lender → search "Acme Textiles" → click "Run Assessment" → see full report with score 720, Grade B, suggested limit ₹50L, decision APPROVE — including a couple of red flags and reason codes
- Same MSME but with poor data → score 480, Grade D, REJECT

## 8. How to run (will be in README.md)
```
# one-time
python -m venv .venv
.venv\Scripts\activate
pip install -r backend/requirements.txt
cd frontend && npm install && cd ..

# run
python run.py            # starts backend on :8000 and frontend on :5173
# open http://localhost:5173
```

## 9. What I will NOT do (out of scope for this prototype)
- Real integrations with GSTN / MCA / CIBIL (simulated with synthetic data only)
- Production-grade KYC, encryption at rest, SOC2 compliance
- Mobile apps (web only)
- Multi-tenancy (single dealer org for demo)
- Real deployment to cloud (code is cloud-ready but not deployed)
